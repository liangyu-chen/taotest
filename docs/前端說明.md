## 1. 專案結構

後端負責「把資料存進 Google 試算表、算班表」，前端負責「顯示畫面、把使用者的操作送給後端」。前端的程式全部在 `src/` 底下。

```
src/
├── main.tsx               入口：把整個 App 掛到網頁上（只呼叫一次）
├── App.tsx                路由：哪個網址顯示哪個頁面
├── styles.css             全部的樣式（外觀），按 class 名稱使用
├── types.ts               資料型別：後端回傳的「資料長什麼樣子」都定義在這
├── api.ts                 「跟後端要資料」的唯一入口，所有頁面都透過它
├── auth.tsx               登入狀態管理：現在誰登入、登入/登出
│
├── components/            共用的小零件（跨頁面使用）
│   ├── Layout.tsx         外框：左側選單＋上方標題列，包住每個頁面
│   ├── MonthNav.tsx       月曆切換器：「‹ 2026 年 8 月 › 本月」
│   └── ui.tsx             更小的共用零件：彈窗 Modal、載入 Spinner、輸入欄 Field、訊息 Toast
│
└── views/                 每個「頁面」一支檔
    ├── Login.tsx          登入頁
    ├── Schedule.tsx       班表總覽（月曆＋自動排班按鈕）
    ├── Availability.tsx   排休與時段（含 Ctrl+C / Ctrl+V 複製貼上）
    ├── Employees.tsx      員工管理（含每人代表顏色）
    ├── ShiftTypes.tsx     班別與人力需求設定
    ├── Settings.tsx       排班規則設定
    ├── Users.tsx          帳號管理
    └── Generate.tsx       自動排班的「前後檢查頁」（已從選單移除，功能改由班表總覽呼叫）
```

**怎麼看一個頁面**：`views/` 底下每個檔，開頭通常先「宣告幾個 useState（頁面的資料）」，中間有「一個 load 函式去跟後端要資料」，最後回傳「JSX（畫面長什麼樣）」。看完一份就知道其他份的套路。

## 2. React 概念速成

以下用本專案實際出現的例子說明。懂了這幾個名詞，就能讀懂大部分程式。

### 2-1. 元件（Component）＝「一個回傳畫面的函式」

React 的畫面是用函式組出來的。每個元件就是一個函式，回傳一段「長得像 HTML」的描述（叫 **JSX**），React 幫你把它畫到瀏覽器上。

以 `components/MonthNav.tsx` 為例：

```tsx
export default function MonthNav({ year, month, onChange }) {
  return (
    <div className="monthnav">
      <button onClick={...}>‹</button>
      <span>{year} 年 {month} 月</span>
    </div>
  )
}
```

- 元件命名開頭大寫（`MonthNav`），用起來像自訂的 HTML 標籤：`<MonthNav ... />`。
- 傳給元件的參數叫 **props**（屬性）。上面的 `year`、`month`、`onChange` 就是 props——由外層（例如 Schedule 頁面）傳進來。

### 2-2. useState＝「會記住、改了會自動重畫的變數」

普通變數改了畫面不會動。`useState` 變數被改時，React 會自動重新執行這個元件、把畫面更新。

```tsx
const [month, setMonth] = useState(8)   // month 目前是 8
...
onClick={() => setMonth(9)}             // 改成 9 → 畫面自動變「9 月」
```

- `useState(初始值)` 回傳一組 `[值, 改值用的函式]`。
- 你**不能**直接寫 `month = 9`，一定要呼叫 `setMonth(9)`，React 才知道要重畫。
- 命名慣例：`[xxx, setXxx]`。

本專案每個頁面都是這樣在管資料的，例如 `Schedule.tsx`：

```tsx
const [assignments, setAssignments] = useState<Assignment[]>([])  // 本月已排的班
const [employees, setEmployees] = useState<Employee[]>([])        // 員工名單
const [loading, setLoading] = useState(true)                     // 是否還在載入
```

### 2-3. useEffect＝「畫面出現之後，去做某件事」

有些事不能直接在元件函式裡做（例如跟後端要資料），因為元件每次重畫都會再跑一次。`useEffect` 讓你在特定時機去做一次。

```tsx
useEffect(() => {
  void load()      // 進到這個頁面時，去後端抓資料
}, [load])         // 依賴陣列：只有 load 改變時才再執行一次
```

- 第二個參數 `[]`（依賴陣列）很重要：
  - `[]`＝只在「進頁面時」執行一次。
  - `[year, month]`＝每當 `year` 或 `month` 改變就重跑。這正是「切換月份就重新抓班表」的原理。
  - 不寫＝每次重畫都跑（通常不是你要的）。

### 2-4. useMemo / useCallback＝「快取」

兩者都是避免白做工：

- `useMemo`：把「計算出來的東西」記下來。只有依賴變了才算一次。
  ```tsx
  // 從幾百筆班表中，建立「哪一天有哪些班」的查詢表；assignments 沒變就不重算
  const slotsByDay = useMemo(() => { ... }, [assignments])
  ```
- `useCallback`：把「函式」記下來，讓它不會每次重畫都變成新函式（常配合 useEffect 依賴使用）。

其實兩者只是效能優化，**看不懂也不影響理解邏輯**，知道「它是快取」就好。

### 2-5. Context＝「全域狀態」

`useState` 是元件自己的狀態，父子之間要用 props 傳。但「目前登入的人是誰」幾乎每個頁面都要用，逐層傳太麻煩。Context 就是在最外層放一份、讓任何元件都能直接讀取。

`auth.tsx` 就是這樣：`AuthProvider` 在最外層（`App.tsx`）包住所有頁面，任何元件呼叫 `useAuth()` 就能拿到：

```tsx
const { user, login, logout } = useAuth()
```

- `user`：目前登入者（null 表示未登入）
- `login / logout`：登入、登出
- 詳見[第三章的登入流程](#3-1-登入)

## 3. 資料怎麼流動

這是本專案最核心、也最常搞混的地方。整件事就是一句話：

> **畫面 → 呼叫 `api()` → 後端 → 回傳 JSON → 存進 `useState` → React 自動重畫**

### 3-1. 登入

```
使用者填帳號密碼
   ↓  Login.tsx 呼叫 useAuth().login(...)
   ↓  auth.tsx 呼叫 POST /api/auth/login
   ↓  後端驗證成功，回傳 { token, user }
   ↓  token 存進瀏覽器 localStorage（api.ts 的 setToken）
   ↓  user 存進 useState（auth.tsx 的 setUser）
   →  整個 App 知道「已登入」→ 跳到首頁
```

之後每次開網站，`auth.tsx` 都會先呼叫 `GET /api/auth/me` 問後端「我的 token 還有效嗎、我是誰」，有效就自動登入，無效就跳去登入頁。

### 3-2. 每一次「跟後端要資料」

所有請求都走 `api.ts` 的 `api(path, options)` 函式，**不要自己直接寫 fetch**。它統一幫你處理三件事：

1. **自動帶上登入憑證**：從 localStorage 拿出 token，加上 `Authorization: Bearer ...` 表頭（`src/api.ts:23`）。
2. **自動解析 JSON**：回傳後端資料；若後端回 `{ error }`，就拋出錯誤，頁面用 `toast()` 顯示。
3. **401（登入過期）自動登出**：token 失效時清掉 token、跳到登入頁。

所以頁面裡要抓資料，寫法都很像：

```tsx
const load = useCallback(async () => {
  const res = await api<{ assignments: Assignment[] }>('/schedule?year=2026&month=8')
  setAssignments(res.assignments)   // 存進 useState → 畫面重畫
}, [])

useEffect(() => { void load() }, [load])   // 進頁面時抓一次
```

### 3-3. 全貌

```
React 頁面（views/*）
    │  呼叫 api('/schedule', ...)         ← 唯一的對外管道，在 src/api.ts
    ▼
後端 Express（server/index.js 起動）
    │  依照網址分派到對應的路由
    ▼
server/routes/*.js   ← 處理請求、檢查權限、做 CRUD
    ▼
server/sheets.js     ← 讀寫 Google 試算表
    ▼
Google 試算表（唯一儲存地方）
```

### 3-4. 「已排的班」如何顯示出來

`Schedule.tsx` 裡有一個自訂 hook `useMonthData`，它把「一個月需要的所有資料」一次抓齊：

| 變數 | 來源 API | 用途 |
|---|---|---|
| `assignments` | `GET /schedule?year&month` | 本月每一天、誰排哪個班 |
| `employees` | `GET /employees` | 員工名單（姓名、代表顏色…） |
| `shiftTypes` | `GET /shift-types` | 班別（早班/晚班、顏色、時段） |
| `availability` | `GET /availability?year&month` | 誰哪天排休/沒空/偏好 |

抓完存進 useState，月曆用這些資料畫出每一格。切換月份時 `year/month` 改變 → `useEffect` 重新抓 → 月曆更新。這就是「資料怎麼流動」的完整例子。

## 4. 以「班表總覽」為完整範例

`views/Schedule.tsx` 是最大的一支頁面（約 730 行），但拆開看只有幾塊：

```
Schedule（頁面本體）
  ├─ useMonthData()         自訂 hook：抓「這個月」的所有資料（見 3-4）
  ├─ 一些 useMemo          建立查詢表：員工ID→員工、班表→格子、排休→查詢
  ├─ dropToAssign()        拖曳員工到某個班別（加入）
  ├─ removeAssignment()    拖曳方塊到下方區塊（移除）
  ├─ renderCell()          畫「月曆的每一格」（上午/下午、姓名方塊、員工圓點）
  ├─ 上方：圖例 + 月曆 + 本月人力彙總
  └─ AssignModal            人力指派彈窗（新增/移除人員、填備註）
```

一段典型的「格子」長這樣，註解已寫在程式裡：

```tsx
// 每一格 = 一天。上半部是排好的班（shift-chip），下半部是每個員工的狀態圓點（avail-dot）
```

讀法建議：先讀 `useMonthData`（資料從哪來）→ 再讀 `renderCell`（資料怎麼畫成格子）→ 最後看拖曳/彈窗怎麼改資料。

## 5. 常見問題 Q&A

**Q：畫面改了但沒反應？**
A：確認是不是用了 `setXxx` 而不是直接賦值（見 2-2）。改完 state 但畫面沒動，通常是直接改了 `useState` 變數本身。

**Q：為什麼 useEffect 一直重跑？**
A：依賴陣列裡放了會一直變的值（例如「每次重畫都是新函式」的 `load`，所以常搭配 `useCallback`）。見 2-3、2-4。

**Q：我要加一個新頁面，要動哪些檔案？**
A：在 `views/` 新增一支元件 → 在 `App.tsx` 加一行 `<Route>` → 想出現在選單的話，在 `components/Layout.tsx` 的 `items` 加一筆。

**Q：後端網址在哪改？**
A：開發時 `vite.config.ts` 的 proxy（`/api` → `http://localhost:3001`）；正式上線由後端直接提供前端檔案，不需改。

**Q：為什麼要 api() 而不是自己 fetch？**
A：`api.ts` 統一處理了「帶 token、解析 JSON、401 自動登出」，頁面就不用重複寫這些，也避免漏掉。
